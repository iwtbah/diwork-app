# diwork-app

**diwork-app 是一个以工作计划为起点、任务为执行载体、工作记录为过程依据的个人工作管理平台。**

帮助用户安排周期工作、拆解长期目标、处理临时任务，并通过工作记录和工作台完成日常复盘。

```text
工作计划 → 生成 / 创建任务 → 执行与更新进度 → 工作记录 → 工作台汇总与复盘
```

> 当前阶段：已完成仓库结构、文档、协作规范与结构检查 CI。Web、桌面端、后端、数据库及产品原型均为预留骨架，尚无可运行的业务应用。下文产品功能与技术架构均为规划。

## 产品功能介绍

一期 MVP 聚焦四个模块，先形成从计划到执行、记录与复盘的完整流程。

| 模块 | 主要功能 | 用户价值 |
|---|---|---|
| 工作台 | 今日任务与快捷完成、本周工作日历、任务汇总与完成率、逾期和临近截止提醒；目标进度按一期范围逐步接入 | 明确今天要做什么、哪些工作有风险 |
| 工作计划 | 日 / 周 / 月周期计划、一次性计划、未来发生日期预览、规则启停与终止、目标创建与子任务拆解 | 提前安排重复工作，把长期目标转为可执行任务 |
| 任务中心 | 周期 / 目标 / 临时任务统一管理，快速新增，设置优先级、状态、执行日期、截止日期与进度，支持筛选和详情查看 | 在同一个入口推动实际工作 |
| 工作记录 | 从任务添加或独立补录，记录工作内容、成果、卡点、耗时、下一步，可同步更新进度并查询历史 | 保留执行事实，为复盘和后续周报提供依据 |

### 工作计划与任务

工作计划负责定义意图与规则，具体执行由任务承载。

| 计划类型 | 任务形成方式 | 示例 |
|---|---|---|
| 周期型计划 | 按规则为每个发生日期生成独立任务实例 | 每周一科室例会 |
| 目标型计划 | 未拆解时对应一个执行任务，拆解后由子任务承载执行 | 在截止日期前完成平台 V1 |
| 一次性计划 | 在指定执行日期形成一次任务 | 安排一次系统升级 |

临时任务可直接在任务中心创建，无需先建立计划。任务来源、执行状态和优先级分别管理。

- 状态：待办、进行中、已暂停、已完成、已取消。
- 优先级：P0 紧急重要、P1 重要、P2 常规、P3 低优先级。
- 快捷筛选：全部、今日、本周、未完成、逾期、已完成，并可按来源、优先级和日期进一步查询。

### 典型使用场景

1. **周期例会**：建立每周一的例会计划，提前查看本周与下周任务；本周完成并保存纪要，下周任务仍保持独立待办。
2. **长期目标**：创建平台开发目标，拆成需求、开发、测试等子任务；每天记录投入、成果和卡点，追踪整体进展。
3. **临时工作**：直接新增紧急排障任务，设置优先级与截止时间，执行后补充记录；也支持没有预建任务的独立工作记录。

## 核心业务规则

以下约束贯穿原型、接口、数据模型和验收：

- **统一任务源**：工作台、任务中心和周日历展示同一批任务；未来甘特图也复用同一数据源。
- **周期生成幂等**：同一规则、同一发生日期只生成一个实例；实例有独立状态、进度及记录。原规划建议默认提前保证未来 14 天实例可见，具体窗口待确认。
- **保留历史事实**：单次改期不影响后续周期；规则变更不得覆盖已完成、取消或实际执行过的历史任务，未来已手动改期的实例需明确处理冲突。
- **目标不重复计数**：拆解后由可执行子任务参与任务统计；目标作为汇总对象。进度支持手动填报或子任务平均汇总，具体模式在实现前明确。
- **状态与进度独立**：逾期由截止日期和状态派生；进度达到 100% 不无条件覆盖完成状态。
- **工作记录可追溯**：一个任务可以有多条记录，一条记录至多关联一个任务，也允许独立记录；进度更新保留变化历史。
- **日期与统计口径明确**：日期按工作时区解释；月末缺失日期、完成率分母和本周统计规则需在实现前确定。

完整字段、异常处理及优先级以 [产品规划 V1.1](./个人工作管理平台_产品功能规划_V1.1.md) 和 [MVP 范围](./docs/mvp/scope.md) 为准。

## 技术架构

采用单仓库（Monorepo）组织多端入口、共享前端模块与后端服务。优先交付 Web，桌面端后续复用页面与业务逻辑。

| 层 | 规划方案 | 当前状态 |
|---|---|---|
| Web | React + TypeScript + Vite | 入口和源码目录预留 |
| UI 与交互 | Tailwind CSS、shadcn/ui、Motion、Lucide React | 尚未接入依赖 |
| 路由、数据与表单 | React Router、TanStack Query、Zustand、React Hook Form + Zod | 尚未接入依赖 |
| 桌面端 | Tauri 2，复用共享 UI 和业务模块 | 阶段二，未初始化 Rust 工程 |
| 后端 | Java + Spring Boot 单体，按业务模块组织 | 源码与测试目录预留，未生成构建工程 |
| 周期调度 | Spring Scheduling，幂等生成与启动补偿 | 尚未实现 |
| 数据库 | 一期首选 SQLite，后续按需求评估 PostgreSQL | 模型、迁移与演示数据目录预留 |
| 数据迁移 | 拟采用 Flyway，先验证 SQLite 支持与分发方案 | 尚未创建迁移脚本 |
| 部署 | Nginx + Web 静态产物 + Spring Boot JAR | 配置与部署目录预留 |
| 工作区与 CI | pnpm workspace；GitHub Actions 执行结构检查 | 已建立；尚无应用构建与业务测试 |

框架与库沿用已有技术方案，具体版本、JDK 兼容性、SQLite 原生驱动和部署环境能力将在应用初始化时验证并锁定。

### 目标部署结构

```text
浏览器 ───────────────→ Nginx ──┬── Web 静态资源
                               └── /api ──→ Spring Boot 单实例
                                               ├── SQLite 文件
                                               └── 周期任务调度

Tauri 桌面端（后续） ──────── API ────────────→ Spring Boot
```

Web 与桌面端均通过 API 访问数据，不直接操作服务端 SQLite 文件。数据库迁移脚本在 `database/migrations` 唯一维护，后端资源打包方式待工程初始化时确定。SQLite 备份采用一致性备份方式，并验证恢复流程。

### 模块职责与依赖边界

| 目录 | 放置内容与边界 |
|---|---|
| `apps/` | Web / 桌面入口与环境组装；可复用业务逻辑放入共享包 |
| `packages/features` | 工作台、计划、任务与工作记录页面及业务逻辑，供两端复用 |
| `packages/ui` | 通用组件与设计令牌，不访问业务 API |
| `packages/api-client` | 统一网络请求、错误处理及契约适配 |
| `packages/types` | 共享类型，不依赖 UI 或平台运行时 |
| `packages/platform` | 隔离浏览器与桌面系统能力，避免共享业务代码直接依赖 Tauri |
| `services/backend` | 单体 API、业务规则、数据访问与周期调度；不运行用户自动化脚本 |
| `database` | 数据模型、迁移与开发演示数据；不存真实数据库文件 |
| `design` | 原型、设计系统与资源；原型按模块和版本组织，使用演示数据 |
| `docs` | 产品、MVP、API、架构和开发文档；重大技术取舍记录 ADR |
| `infra` | 部署配置与运维流程，需结合目标服务器能力验证 |
| `tests` | 跨模块及端到端验证；模块单元测试与源码就近维护 |
| `.agents/skills` | AI 开发助手的项目技能约定，与产品未来的 AI Agent 功能分开管理 |

前端依赖方向为：应用入口 → `features` → `ui` / `api-client` / `platform` / `types`。共享包不反向依赖 `apps/*`。pnpm workspace 管理 `apps/*` 与 `packages/*`，Java 和 Rust 工程使用各自构建工具。

## 开始协作与结构检查

1. 阅读 [产品规划](./个人工作管理平台_产品功能规划_V1.1.md) 和 [技术方案](./个人工作管理平台_技术选型与部署方案_V1.0.md)。原始文件保留在根目录。
2. 阅读 [协作规则](./AGENTS.md)、[开发指南](./docs/development/README.md) 和 [MVP 计划](./docs/mvp/README.md)。
3. 使用 Node.js 22 或以上，在仓库根目录执行结构检查。
4. 按 MVP 里程碑初始化可运行应用，提交已验证的依赖版本、锁文件及真实运行命令。

```sh
npm run check
```

当前检查使用 Node 内置模块，无需先安装第三方依赖；覆盖预留目录、工作区描述、仓库内 Markdown 相对文件链接和骨架配置。检查脚本不访问网络，不验证文档标题锚点或业务行为。

当前没有可执行的 `dev`、应用构建或业务测试命令；CI 仅验证仓库骨架。应用接入后必须补充类型检查、真实构建和相关业务测试。项目专用 AI Skills 尚未添加，数据库迁移、部署脚本和原型也尚未实现。
