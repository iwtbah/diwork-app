# ADR 0001：多端仓库与文档结构

- 日期：2026-10-19
- 状态：目录组织已采用；具体框架版本及运行环境待验证

## 背景

已有产品方案要求先交付 Web MVP，再复用 UI 支持桌面端；后端使用 Java 单体，内网部署优先 SQLite。需要给原型、业务规划、应用实现及 AI 协作建立清晰位置。

## 决策

- 使用单仓库，以 `apps/web` 和 `apps/desktop` 管理入口，以 `packages/*` 管理共享前端模块。
- 后端位于 `services/backend`，数据库模型与迁移位于 `database`。
- 原型位于 `design/prototypes`；一期规划位于 `docs/mvp`。
- 根 `AGENTS.md` 管理 AI 协作，项目技能位于 `.agents/skills`。
- 前端采用 pnpm workspace，不预先引入重型构建编排；骨架检查使用 Node 内置能力。
- 保留两份已有规划原文件，通过文档索引引用。

## 后果与验证

共享 UI 能支撑多入口，但要约束平台接口与依赖方向。Java / Rust 构建需独立接入。M1 必须验证依赖版本、SQLite 驱动和迁移能力，并补充真实构建与测试；当前目录检查不证明应用可运行。
