# 开发指南

## 当前可执行操作

安装 Node.js 22 或以上，在仓库根目录执行：

```sh
npm run check
```

脚本不依赖第三方包，检查目录、JSON 工作区描述、仓库内 Markdown 链接和骨架配置。成功只表示结构符合约定。

目前没有应用启动、构建或业务测试命令。无需为了目录检查执行依赖安装。后续实际初始化应用时选择并固定 pnpm 版本，提交 `pnpm-lock.yaml`；Java / Rust 同步提交对应构建配置与适用锁文件。

## 后续初始化顺序

1. 阅读技术方案，验证目标服务器 JDK、文件目录、Nginx 和原生驱动能力。
2. 锁定 React / Vite / TypeScript、Spring Boot / JDK、SQLite JDBC 和迁移工具的兼容版本。
3. 在现有目录内初始化 Web 与后端；保留已有说明，避免生成嵌套项目或覆盖原文件。
4. 明确 API 契约来源、迁移打包、日期语义和本地配置；提供无密钥的 `.env.example` 或应用配置示例。
5. 接入真实检查、测试和 CI，再按 MVP 流程实现功能。

## 配置与数据

仅在真正消费配置后提交对应示例，避免提供实际无人读取的环境变量。前端公开配置与后端私有配置必须分开。本地数据库使用 `.runtime/` 等忽略目录；任何真实用户数据不得提交。

## 发布

一期交付 Web 静态产物与 Spring Boot JAR，由 Nginx 提供入口。部署参数及运维脚本位于 `infra`；目前均为预留。实际发布前验证备份、迁移、健康检查与回滚流程。
