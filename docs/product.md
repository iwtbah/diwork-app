# 个人工作管理平台｜产品功能与业务模型规划 V1.1

> 文档类型：产品功能规划 / 业务规则  
> 版本：V1.1｜2026-10-19  
> 范围：明确一期 MVP，并记录二期及后续演进方向。本文**不涉及 UI 设计、框架选型和技术实现**。

## 1. 产品定位与发展方向

**定位：**以工作计划为起点、任务为执行载体、工作记录为过程依据的个人工作管理平台；长期逐步发展为以任务为核心的工作自动化平台。

**核心价值：**让用户能够规划工作、自动获得周期待办、推动长期目标、留下可追溯执行记录，并快速完成工作复盘。

**长期闭环：**工作计划 → 生成/创建任务 → 人工或自动化执行 → 记录与验证结果 → 更新进度 → 工作台汇总与复盘。

### 1.1 产品阶段

| 阶段 | 定位 | 范围 |
|---|---|---|
| 一期（MVP） | 个人工作计划与执行管理 | 工作台、工作计划、任务中心、工作记录；周期生成；目标拆解与基础进度 |
| 二期 | 任务自动化 | 任务关联自动化能力、手动/审核后/自动执行、执行结果与异常处理 |
| 三期 | 多用户与能力共享 | 用户空间、自动化能力库、分享与复用、权限与授权、版本治理 |
| 远期 | 智能工作代理 | 在授权与审核边界内，AI 辅助规划、选择和组合自动化能力 |

**一期边界：**不实现脚本执行、能力市场、复杂组织协作、AI Agent；但业务概念应避免与未来扩展相冲突。

## 2. 核心业务对象与关系

| 对象 | 业务含义 | 典型例子 |
|---|---|---|
| 工作计划（Plan） | 定义未来希望完成的周期性工作或目标 | 每周一科室例会；11月底完成系统开发 |
| 周期规则（Recurrence） | 定义周期计划何时产生任务 | 每周一 09:00；每月 5 日 |
| 任务（Task） | 某次真实需要执行的工作，有独立状态、日期和进度 | 10月26日科室例会；实现登录接口 |
| 工作记录（Work Log） | 某天实际做了什么、成果、卡点、进度变化 | 10月19日开发登录接口 3 小时 |
| 目标里程碑/子任务 | 目标计划的可执行拆分 | 需求分析、前端开发、测试验收 |
| （未来）自动化能力 | 可复用的执行方式，与任务独立 | 预订会议室、生成周报 |
| （未来）自动化执行记录 | 某次自动执行及校验的结果 | 会议室预订成功/失败 |

```text
工作计划 ──┬── 周期型计划 ── 周期规则 ──(按日期生成)──┐
          └── 目标型计划 ── 目标/子任务 ───────────┤
                                                    ▼
临时任务 ───────────────────────────────────────→ 统一任务中心
                                                    │
                                       执行 / 更新状态 / 记录进度
                                                    ▼
                                               工作记录
                                                    │
                                   ┌────────────────┴───────────────┐
                                   ▼                                ▼
                                 工作台                        目标进度/甘特图
```

**关键原则：**

1. **计划不是执行记录，任务是执行单元，工作记录是事实凭证。**
2. 任务中心只有一份任务数据；工作台、周日历、甘特图只是不同观察方式。
3. 任务有三种**来源**：周期计划、目标计划、手动临时新增；“来源”与“状态”“优先级”独立。
4. 同一任务可以关联多条工作记录；一条工作记录至多关联一个任务（一期允许不关联）。
5. 周期规则变更不得篡改已发生的历史执行事实。

## 3. 一期产品功能架构

```text
个人工作管理平台
├── 工作台
│   ├── 今日任务 / 拖动状态 / 快捷完成
│   ├── 工作日历（按月翻阅）
│   ├── 本周任务汇总与完成率
│   ├── 任务内逾期及临近截止标记
│   └── 进行中目标进度
├── 工作计划
│   ├── 计划列表与查询
│   ├── 新建周期型计划：日/周/月/不循环
│   ├── 周期规则启停、终止、单次例外
│   ├── 新建目标型计划
│   ├── 目标拆解为可执行子任务
│   └── 计划执行历史
├── 任务中心
│   ├── 周期任务 / 目标任务 / 临时任务统一列表
│   ├── 快速创建临时任务
│   ├── 优先级、状态、计划与截止日期
│   ├── 今日/本周/待办/逾期等筛选
│   ├── 任务编辑及完成
│   └── 任务详情与关联工作记录
└── 工作记录
    ├── 从任务快捷添加 / 独立添加
    ├── 选择任务 ID 自动带出基本信息
    ├── 内容、成果、卡点、耗时、下一步
    ├── 可选更新任务进度
    └── 按任务与日期查询历史
```

> “新建工作计划”是工作计划模块内的统一操作入口，不必作为独立的一级业务模块。

## 4. 工作计划

### 4.1 计划类型

| 类型 | 定义 | 任务落地方式 |
|---|---|---|
| 周期型计划 | 按固定规则反复执行 | 系统按执行日期生成独立任务实例 |
| 目标型计划 | 在期限内达成一个结果 | 未拆解时对应一个执行任务；拆解后由子任务承载执行 |
| 不循环的一次性计划 | 只安排一次的计划工作 | 到指定执行日期形成一个任务 |

> 一次性计划与临时任务的区别：前者由计划模块正式规划，后者在任务中心直接快速创建。两者都只形成一条执行任务。

### 4.2 周期型计划字段（一期）

计划名称、描述、优先级、生效日期、循环方式（日/周/月）、执行日或日期、计划开始时间（可选）、预计时长（可选）、结束条件（永不/指定日期/指定次数）、启用状态；可选关联分类。

**周期规则：**

- 日循环：每天或每隔 N 天（一期可先实现每天）。
- 周循环：选择星期一至星期日，可多选；如每周一科室例会。
- 月循环：选择每月第 N 日；月底不存在该日期时明确选择“跳过”或“当月最后一天”，不能默默顺延。
- 不循环：指定单次计划执行日期。
- 日期及时间以用户的工作时区解释，避免跨时区错日。

**生成与可见性要求：**

- 创建规则后，用户立即可以预览未来计划发生日期。
- 任务中心应能提前看到下一周的周期实例，不应等上一周期任务完成才生成。
- 建议默认保证**未来 14 天**实例可用；属于产品规则建议，可在后续配置中调整。
- 对同一规则与同一发生日期只生成一次；重复运行不产生重复任务。
- 每次实例拥有独立完成状态、进度、日期及工作记录。
- 周日历直接展示对应任务实例，无须复制到另一套“周计划数据”。

**变更和异常规则：**

| 场景 | 应有行为 |
|---|---|
| 本周例会取消 | 仅跳过/取消本次实例，后续不变 |
| 本周从周一调整到周二 | 只修改本次任务日期 |
| 此后每周都改为周二 | 从指定生效日调整规则及未来待执行实例 |
| 暂停周期计划 | 暂停产生新的实例；已发生记录保留 |
| 终止周期计划 | 停止未来生成，不删除历史 |
| 修改计划名称/规则 | 保留已执行任务的历史信息；明确未来任务处理范围 |

默认不允许后台规则更新默默覆盖**已完成、取消或已实际执行**的历史任务。对未来已手动改期的任务，应提供明确的冲突提示或保留例外。

### 4.3 目标型计划

**主要字段：**目标名称、目标说明、开始日期、截止日期、优先级、状态、完成标准、当前进度、子任务/阶段（可选）。

**规则：**

- 新建目标后，未拆解时可直接建立一个目标执行任务，用于跟踪和记录。
- 拆解为子任务后，任务中心展示可执行子任务；目标本身作为汇总对象，不与子任务重复统计“应完成任务数”。
- 子任务有自己的执行区间、负责人（多用户阶段再用）、状态、进度、工作记录；后续支持里程碑和依赖关系。
- 目标进度模式：MVP 支持**手动填报**或**子任务平均汇总**二选一；后续可按预估工作量/权重汇总。
- 目标延期与任务逾期分开统计；达到 100% 是否自动完成需明确规则（建议显式完成确认）。

**甘特图业务需求（一期预留，二期实现）：**按任务开始/截止日期展现时间条，显示任务进度、里程碑与目标层级；支持查看计划与实际进展，进度变化可追溯。甘特图不是另一套数据源。当前桌面视觉原型先提供只读甘特窗口，验证阶段与日期的展示；不代表已实现完整甘特业务。缺少开始日期时不虚构区间，仅有截止日期显示截止点；无日期保留为待安排，日期倒置提示校正。

## 5. 任务中心

### 5.1 任务来源

1. **周期任务**：由周期计划在某个发生日生成，如 10月26日科室例会。
2. **目标任务**：由目标型计划直接对应或拆解产生，如完成用户模块。
3. **临时任务**：在任务中心快速创建，不依赖工作计划。

### 5.2 一期任务主要属性

任务 ID、名称、描述、来源类型、关联计划（如有）、优先级、计划执行日期或时间、截止日期、任务状态、当前进度、预计工时（可选）、实际工时汇总、完成时间（若完成）、备注/卡点。

| 维度 | 规则 |
|---|---|
| 状态 | 待办、进行中、已暂停、已完成、已取消 |
| 优先级 | P0 紧急重要；P1 重要；P2 常规；P3 低优先级 |
| 逾期 | **派生标记**，不是状态；截止日期已过且未完成/未取消的任务才标逾期 |
| 今日任务 | 计划执行日期为今天；可同时突出今天到期但尚未完成的任务 |
| 未完成待办 | 待办、进行中、已暂停等未终结任务，可进一步按优先级筛选 |
| 进度 | 0–100%，更改留痕；进度 100% 不应无条件覆盖任务状态 |

**任务筛选：**日期（全部时间、今日、本周、本月）与状态条件（全部、未完成、待办、进行中、逾期、已暂停、已完成、已取消）分别选择，可叠加来源、优先级与名称。未完成包含待办、进行中、已暂停；逾期仍是派生条件，不新增任务状态。日期按执行或截止日期命中，范围内同一任务只统计一次。

**关键操作：**新增临时任务、编辑、改期、调整优先级、开始/暂停/完成/取消、补充记录、查看历史。

**任务视图：**任务中心支持卡片式与条形目录式，切换保留筛选。首页与任务中心卡片使用同一任务源和视觉组件；首页按状态分栏，可拖动卡片更新状态，遵守同一状态转换与进度留痕规则。任务中心在筛选下直接展示连续卡片网格，不重复显示状态分组；状态在每张卡片中保留文字说明。拖动取消或未落到有效状态列时不修改任务；首页仅通过拖动（含键盘拖动）修改状态，卡片不提供状态下拉；任务中心仍可从详情操作，保留撤销入口。

## 6. 工作记录

### 6.1 填写逻辑

工作记录可以从任务详情发起，自动关联任务 ID 并带出任务名称、类型、计划日期等只读信息；也允许从工作记录模块新增后选择任务。

**一期推荐字段：**记录日期、关联任务（可空）、实际工作内容、成果、卡点/问题、下一步工作、耗时（可选）、本次更新后的任务进度（可选）。

**重要规则：**

- 一个任务可以拥有多条工作记录；工作日志不会覆盖旧记录。
- 允许**独立工作记录**，用于没有预建任务的临时会议/协助工作；其内容不纳入任务完成率。
- 选择更新进度时，应明确告知“保存记录并把任务进度更新为 X%”，同时保留此前进度和发生时间。
- 工作记录中的耗时是事实投入，不等于任务完成百分比。
- 记录已关联的任务名称即使以后被修改，仍应能追溯记录时的必要上下文。

### 6.2 工作记录的业务价值

支持按日期、任务、目标和周期计划查询；可用于周报素材、目标推进轨迹、常见卡点分析及后续自动执行事实记录。

## 7. 工作台

定位为**工作执行首页**，不仅显示数据，还要支持高频操作。首次进入先展示工作日历；进入工作台时，日历收拢到右上角成为闭合日历簿。点击日历簿可再次展开，并保留正在查看的月份及日期。

| 功能 | 业务要求 |
|---|---|
| 今日任务 | 展示当天任务、优先级、状态；可快速完成或进入记录 |
| 总体汇总 | 今日任务数、未完成、逾期、本周完成率；用今日完成环与本周日节奏图表达，点击日期或逾期入口进入对应筛选 |
| 工作日历（按月翻阅） | 按月展示来自任务中心的安排，支持查看历史月份、下个月和回到本月；尚未生成的周期日期明确标记为预览 |
| 目标进度 | 展示进行中目标、截止时间、整体进度、当前阶段与各阶段推进情况；点击查看只读甘特图，可继续查看任务详情 |
| 任务风险标记 | 即将到期、已逾期、暂停及有卡点信息在任务卡片或列表中表达；首页不另设风险区域 |

**统计口径需要统一：**本周计划任务基于执行/截止日期的明确规则统计；“本周完成”按完成日期或本周应做任务的完成数量应分别命名，避免混淆。取消任务是否计入分母必须明确；建议默认不计入完成率分母，另统计取消数量。

新建任务、子任务与工作记录使用居中窗口，窄屏限制在可视区域并允许内容滚动。应用内窗口、任务搜索与二次确认从触发按钮展开、向原入口收拢，使用类似 macOS 神奇效果的拉伸过渡；尊重减少动态效果设置，支持键盘关闭与焦点返回。日历保留独立的纸张翻页和日历簿收拢交互。

目标阶段来自任务的显式阶段归属；未归属任务显示为“执行推进”。阶段进度按该阶段有效任务平均汇总，只有阶段内任务均显式完成才显示阶段完成；目标整体进度继续按全部有效任务汇总，不使用阶段平均值替代，也不因进度 100% 自动完成目标。

## 8. 核心业务流程与验收示例

### 场景 A：科室例会自动出现

1. 创建「科室例会」，选择周循环、周一 09:00 生效。
2. 工作计划页面预览未来发生日期。
3. 系统生成本周及下周对应的独立任务。
4. 任务中心和工作日历同步显示同一批任务。
5. 本周完成并记录纪要；下周仍保留独立待办。

**验收重点：**无重复生成、下周提前可见、修改单次不影响以后、历史状态不丢失。

### 场景 B：目标计划持续推进

1. 创建「11月30日前完成平台 V1」，设置期限和完成标准。
2. 拆成需求、开发、测试等子任务。
3. 每天选择相应任务写工作记录，更新进度和卡点。
4. 工作台展示目标进度；后续甘特图展示任务时间条与进度。

**验收重点：**目标与子任务不重复计数、进度来源清楚、变更可追溯。

### 场景 C：临时工作

1. 用户快速创建「排查线上问题」，设置 P0 与今日截止。
2. 任务立即进入今日待办；完成后可添加工作记录。
3. 即使没有预先建立任务，也允许补录一条独立工作日志。

**验收重点：**操作步骤少、不强制建立工作计划。

## 9. 功能优先级与版本边界

| 模块 | P0：一期必须 | P1：后续强化 | P2：远期增强 |
|---|---|---|---|
| 工作台 | 今日任务、可翻月日历、汇总、逾期标记 | 目标进度聚合、趋势分析 | 自定义组件 |
| 工作计划 | 周期日/周/月、一次性、目标创建、自动生成 | 单次/以后高级改期、执行分析、里程碑 | 复杂工作日与节假日规则 |
| 任务中心 | 三来源统一、卡片／条形目录、临时任务、状态拖动与筛选 | 批量操作 | 智能排序 |
| 工作记录 | 关联/独立记录、内容/卡点/进度历史 | 工时统计、自动周报素材 | 工作过程分析 |
| 甘特图 | 一期保留结构和时间字段 | 基础时间轴、进度及里程碑 | 依赖关系与基线比较 |
| 自动化 | 无执行功能 | 自动化能力绑定与执行 | 共享能力市场与智能编排 |
| 多用户 | 明确归属概念 | 账号、个人数据隔离 | 团队共享与权限体系 |

> 建议一期优先做好闭环，不把完整甘特图、团队协作、脚本市场作为一期交付条件。
